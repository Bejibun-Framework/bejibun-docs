Bejibun reads cookies through Bun's native `request.cookies` and
writes them through dedicated methods on the**`Response` facade** -- no manual header juggling required.

## Reading cookies

`Bun.BunRequest` exposes `request.cookies`, a `CookieMap` built from the incoming `Cookie` header:

```ts app/controllers/SessionController.ts
import BaseController from "@bejibun/core/bases/BaseController";

export default class SessionController extends BaseController {
    public async show(request: Bun.BunRequest): Promise<Response> {
        const sessionId = request.cookies.get("session_id");

        return super.response.setData({
            session: sessionId
        }).send();
    }
}
```

`CookieMap` behaves like a regular `Map` -- `.get()`, `.has()`, `.size`, and `for...of` all work as expected.

## Writing cookies

Set cookies with `setCookie()`, chained the same way as `setData()` or `setMessage()`.
It's applied as a`Set-Cookie` header automatically on `.send()` and `.stream()`, alongside your existing CORS headers.

```ts app/controllers/SessionController.ts
public async login(request: Bun.BunRequest): Promise<Response> {
    const body = await super.parse(request);

    return super.response
        .setMessage("Logged in")
        .setCookie("session_id", crypto.randomUUID(), {
            httpOnly: true,
            secure: true,
            sameSite: "lax",
            path: "/",
            maxAge: 60 * 60
        })
        .send();
}
```

<Warning>
    Always set security attributes on session cookies: `httpOnly` (block JS access),
    `secure` (HTTPS only, in production), and an appropriate `sameSite` value to mitigate CSRF.
</Warning>

Set multiple cookies in one call with `setCookies()` -- each entry can carry its own options:

```ts
return super.response
    .setCookies([
        {
            key: "session_id",
            value: sessionId,
            options: {
                httpOnly: true,
                secure: true
            }
        },
        {
            key: "theme",
            value: "dark",
            options: {
                maxAge: 60 * 60 * 24 * 30
            }
        }
    ])
    .send();
```

## Deleting cookies

`deleteCookie()` expires a cookie. It only accepts `domain` and `path` --
these must match the values the cookie was originally set with,
or the browser will treat it as a different cookie and won't clear it.

```ts
public async logout(request: Bun.BunRequest): Promise<Response> {
    return super.response
        .setMessage("Logged out")
        .deleteCookie("session_id", {
            path: "/"
        })
        .send();
}
```

`deleteCookies()` clears several at once:

```ts
return super.response
    .deleteCookies([
        {
            key: "session_id",
            options: {
                path: "/"
            }
        },
        {
            key: "theme"
        }
    ])
    .send();
```

### Available methods

| Method                            | Effect                                                       |
| --------------------------------- | ------------------------------------------------------------ |
| `setCookie(key, value, options?)` | Set a single cookie                                          |
| `setCookies(cookies)`             | Set multiple cookies, each with its own options              |
| `deleteCookie(key, options?)`     | Expire a single cookie (`domain` / `path` only)              |
| `deleteCookies(cookies)`          | Expire multiple cookies, each with its own `domain` / `path` |

`options` accepts Bun's native `CookieInit` shape --
`domain`, `path`, `expires`, `maxAge`, `httpOnly`, `secure`,`sameSite`, and `partitioned`.

<Tip>
    Cookies are applied on top of CORS headers automatically, on both `send()` and `stream()`.
    You no longer need to return a raw `Response` or merge headers by hand to set a cookie.
</Tip>

As of v0.6.0, storage lives in the standalone
[`@bejibun/storage`](https://github.com/Bejibun-Framework/bejibun-storage) package rather than `@bejibun/core`.
Install it separately and import the `Storage` facade from `@bejibun/storage`.

The `Storage` facade provides one API for working with files whether they live on the local filesystem or in
S3-compatible object storage. Disks are configured once and selected by name, so switching the backing store does not
change your application code.

## Installation

```bash
bun ace install @bejibun/storage
```

The command installs the package and copies its configuration file into `config/storage.ts`.

## The Storage facade

Import `Storage` from the package root and call a method directly. Every operation runs against the default disk unless
you select one with `disk()`:

```ts
import Storage from "@bejibun/storage";

await Storage.exists("path/to/file.ext"); // Promise<boolean>
await Storage.missing("path/to/file.ext"); // Promise<boolean>
await Storage.get("path/to/file.ext"); // Promise<Bun.BunFile | Bun.S3File>
await Storage.put("path/to/file.ext", content);
await Storage.copy("path/to/file.ext", "path/to/copy.ext");
await Storage.move("path/to/file.ext", "path/to/new.ext");
await Storage.delete("path/to/file.ext");
```

| Method                                | Returns                              | Description                          |
| ------------------------------------- | ------------------------------------ | ------------------------------------ |
| `exists(path)`                        | `Promise<boolean>`                   | Whether the file exists              |
| `missing(path)`                       | `Promise<boolean>`                   | Whether the file does not exist      |
| `get(path)`                           | `Promise<Bun.BunFile \| Bun.S3File>` | Retrieve a file instance             |
| `put(path, content, options?)`        | `Promise<void>`                      | Write content to a path              |
| `copy(source, destination, options?)` | `Promise<void>`                      | Copy a file to a new location        |
| `move(source, destination, options?)` | `Promise<void>`                      | Move a file to a new location        |
| `delete(path)`                        | `Promise<void>`                      | Delete a file                        |
| `metadata(path)`                      | `Promise<Stats \| Bun.S3Stats>`      | Return file statistics               |
| `size(path)`                          | `Promise<number>`                    | Return the file size in bytes        |
| `mimeType(path)`                      | `Promise<string>`                    | Return the file MIME type            |
| `lastModified(path)`                  | `Promise<Date>`                      | Return the last modification date    |
| `disk(name)`                          | `StorageBuilder`                     | Select a configured disk by name     |
| `build(disk)`                         | `StorageBuilder`                     | Use an ad-hoc disk for one operation |

`disk()` and `build()` return a builder, so they must be called before the terminal file operation and can be chained:

```ts
await Storage.disk("s3").put("reports/q2.pdf", content);
```

Public URLs are not generated by the facade. They come from the `url` key on the disk configuration (see
[`Disks`](#disks)); the facade itself has no `url()` method.

## File metadata

Inspect a file without reading its contents:

```ts
const metadata = await Storage.metadata("uploads/avatar.png"); // full stats
const size = await Storage.size("uploads/avatar.png"); // bytes
const mimeType = await Storage.mimeType("uploads/avatar.png"); // e.g. "image/png"
const lastModified = await Storage.lastModified("uploads/avatar.png"); // Date
```

These helpers work on every driver and resolve to the same values on local and S3 storage.

<Note>
    `get()` returns a file instance (`Bun.BunFile` or `Bun.S3File`), not the raw contents. Read the contents with
    `.text()`, `.json()`, or `.arrayBuffer()`:

    ```ts
    const file = await Storage.get("path/to/file.ext");
    const contents = await file.text();
    ```

</Note>

## Disks

Disks are defined in `config/storage.ts`. A `local`, a `public`, and an `s3` disk ship by default:

```ts config/storage.ts
import App from "@bejibun/app";
import StorageDiskDriverEnum from "@bejibun/storage/enums/StorageDiskDriverEnum";

const config: Record<string, any> = {
    default: env("FILESYSTEM_DISK", "local"),

    disks: {
        local: {
            driver: StorageDiskDriverEnum.Local,
            root: App.Path.storagePath("app")
        },

        public: {
            driver: StorageDiskDriverEnum.Local,
            root: App.Path.storagePath("app/public"),
            url: `${env("APP_URL")}/storage/public`
        },

        s3: {
            driver: StorageDiskDriverEnum.S3,
            endpoint: env("S3_ENDPOINT"),
            region: env("S3_REGION"),
            bucket: env("S3_BUCKET"),
            access_key_id: env("S3_ACCESS_KEY_ID"),
            secret_access_key: env("S3_SECRET_ACCESS_KEY"),
            url: ""
        }
    }
};

export default config;
```

The `default` key names the disk used when no disk is selected. `StorageDiskDriverEnum` exposes `Local` and `S3`,
whose string values match the `driver` keys shown above.

<Warning>
    **Breaking change (v0.6.0):** move your disk config from `config/disk.ts` to
    `config/storage.ts`, and update imports from `@bejibun/core/facades/Storage` and
    `@bejibun/core/enums/DiskDriverEnum` to `@bejibun/storage` and
    `@bejibun/storage/enums/StorageDiskDriverEnum`. `StorageException` moves with it.
</Warning>

### Selecting a disk

Pass a disk name to `disk()` to run operations against that disk:

```ts
await Storage.disk("public").put("avatars/photo.png", content);
await Storage.disk("s3").get("reports/q2.pdf");
```

### Ad-hoc disks

Build a disk at runtime without adding it to the config:

```ts
import App from "@bejibun/app";
import StorageDiskDriverEnum from "@bejibun/storage/enums/StorageDiskDriverEnum";

await Storage.build({
    driver: StorageDiskDriverEnum.Local,
    root: App.Path.storagePath("custom")
}).put("file.txt", content);
```

## Drivers

<CardGroup cols={2}>
    <Card title="Local" icon="hard-drive">
        Backed by `Bun.file()` and `Bun.write()`, resolved against the disk's `root`. Requires
        `root`.
    </Card>
    <Card title="S3" icon="cloud">
        Backed by `Bun.S3Client`. Requires `endpoint`, `access_key_id`, and `secret_access_key`.
        Supports ACLs, storage classes, and multipart options.
    </Card>
</CardGroup>

<Tip>
    The local and S3 drivers share the same method signatures, so switching a disk from `local` to
    `s3` requires no code changes, only configuration.
</Tip>

Bejibun throttles traffic with a built-in rate limiter applied per client IP,
plus a `RateLimiter` facade for limiting specific actions.

<Note>
    As of v0.6.0, the `RateLimiter` facade lives in the standalone
    [`@bejibun/limiter`](https://github.com/Bejibun-Framework/bejibun-limiter) package rather than `@bejibun/core`.
    `RateLimiterMiddleware` is unaffected -- it's still exported from `@bejibun/core` and works exactly as before,
    now using `@bejibun/limiter` internally.
</Note>

## Global rate limiting

The `RateLimiterMiddleware` is applied to all routes when enabled in `config/performance.ts`:

```ts config/performance.ts
const config: Record<string, any> = {
    middlewares: {
        limiter: true,
        maintenance: true
    }
};

export default config;
```

Tune the threshold in `config/limiter.ts`:

```ts config/limiter.ts
const config: Record<string, any> = {
    limit: 30,
    duration: 60 // seconds
};

export default config;
```

A client exceeding the limit receives a `RateLimiterException` response (too many requests).
Limits are keyed per client IP and backed by the [cache](/v0.6/guides/caching/cache) layer.

## Limiting specific actions

Install the standalone package, then use the `RateLimiter` facade to throttle a particular operation -- for
example, OTP sends or login attempts:

```bash
bun ace install @bejibun/limiter
```

```ts
import RateLimiter from "@bejibun/limiter";

// run the callback only if under the limit
await RateLimiter.attempt("send-otp:user-1", 5, async () => {
    await sendOtp();
}, 60);

// check without consuming an attempt
const blocked = await RateLimiter.tooManyAttempts("send-otp:user-1", 5);

// reset the counter
await RateLimiter.clear("send-otp:user-1");
```

| Method                                     | Description                       |
| ------------------------------------------ | --------------------------------- |
| `attempt(key, limit, callback, duration?)` | Run `callback` if under the limit |
| `tooManyAttempts(key, limit, duration?)`   | Whether the limit is exceeded     |
| `clear(key)`                               | Reset the counter for a key       |

<Note>
    When omitted, `limit` and `duration` default to `60` and `60` seconds respectively.
</Note>

<Tip>
    Choose a key that identifies the actor and action together (for example `login:{email}`),
    so limits are scoped precisely.
</Tip>

<Warning>
    **Breaking change (v0.6.0):** if you're importing `RateLimiter` from `@bejibun/core/facades/RateLimiter`, switch
    to `import RateLimiter from "@bejibun/limiter";`. `config/limiter.ts` keeps its existing `limit` / `duration`
    shape, so no config changes are needed.
</Warning>
